# DevScrolls Content Schema & Frontmatter Specification

This specification is extracted directly from `src/content.config.ts` and `src/content/_taxonomy.ts`. Any article generated by the AI blog pipeline MUST strictly adhere to this schema to pass Astro build validation.

---

## 1. Frontmatter Zod Schema Rules

Every article is stored as Markdown in `src/content/articles/<slug>.md`.

```yaml
---
title: "Article Title Here" # STRING: Strictly <= 70 characters (<= 60 preferred for SEO)
description: "SEO description summarizing the key thesis." # STRING: Strictly between 100 and 160 characters
publishDate: 2026-11-11 # DATE: YYYY-MM-DD
updatedDate: 2026-11-12 # OPTIONAL DATE
category: "frontend" # ENUM: Must be one of the 6 valid categories below
tags: ["react", "performance"] # ARRAY: Max 5 items from the 7 valid tags below
heroImage: "/<slug>-hero.webp" # STRING: Path to WebP image in /public/
heroImageAlt: "Descriptive alt text for accessibility" # STRING: Required, min length 1
draft: false # BOOLEAN: false for published articles
canonical: "https://devscrolls.dev/articles/<slug>/" # OPTIONAL URL
series: "Interview Series" # OPTIONAL STRING
seriesOrder: 1 # OPTIONAL INTEGER
---
```

---

## 2. Controlled Taxonomy (Strict Enums)

### Allowed Categories (Exact 6)
- `frontend` (Frontend Scrolls: UI, frameworks, client-side architecture)
- `backend` (Backend Scrolls: APIs, databases, server logic)
- `ai` (AI Scrolls: Machine learning, agents, data engineering)
- `architecture` (Architecture Scrolls: System design, scalable patterns)
- `interviews` (Interview Scrolls: Real-world technical interview breakdowns and questions)
- `tutorials` (Tutorial Scrolls: Step-by-step guides and how-tos)

### Allowed Tags (Exact 7, Maximum 5 per post)
- `react`
- `typescript`
- `astro`
- `css`
- `performance`
- `accessibility`
- `system-design`

## 3. Article Formatting & Body Structure

1. **BLUF (Bottom Line Up Front):** The very first paragraph must be bolded (`**...**`), providing the core thesis or takeaway within 150 words.
2. **Headings:**
   - Use `## ` (H2) for main sections and `### ` (H3) for subsections.
   - **NO EMOJIS IN HEADINGS:** Headings must be clean, professional text.
3. **Code Blocks:**
   - 5 to 10 lines max showing the critical logic.
   - No 100-line boilerplate.
4. **Banned LLM Words:**
   - Never use: *delve, robust, landscape, in conclusion, tapestry, seamless, game-changer*.
5. **Internal Linking:**
   - Cross-link contextually to tools (`/tools/pii-scrubber/`, `/tools/jwt-debugger/`, `/tools/json-formatter/`, `/tools/daily-scroll/`) or existing articles (`/articles/<slug>/`).
