# 10 Pro Tips to a Smarter UX Design Process — Extraction Notes

## PDF Metadata
- **Title:** 10 Pro Tips to a Smarter UX Design Process
- **Authors:** Jessica Lowry & Jerry Cao, UXPin Inc., 2015
- **Page count:** 23 pages

## Core Theses
1. Process generates creativity, not the opposite.
2. Define the problem before the solution.
3. Design is documentation that tells a story.
4. Test cheap and early.
5. Collaboration beats isolation.
6. Process must adapt to real constraints.

## The 10 Tips

### Tip 1 — Define the Problem First (p. 6-7)
"How Might We..." open-ended frame. Most "obvious problems" are symptoms. Whack-a-mole = real problem unidentified.

### Tip 2 — Know Your User Like an Old Friend (p. 8-9)
Cannot design for "everybody." Pinpoint specific user; create personas; map scenarios. **Scope creep is a direct result of not knowing users well enough.**

### Tip 3 — Consider Extreme Solutions (p. 9-11)
Break conventions on purpose. Storyboard. Inspiration outside your industry. Duolingo cited ($470M valuation 2015) for unconventional game-like learning.

### Tip 4 — Establish a Hypothesis (p. 11-12)
Wambach framework: **"If [action] then [outcome] because [customer need/problem]."** Design's thesis statement.

### Tip 5 — Diverse Critique Group with Final Decider (p. 13)
Think Tank of varied backgrounds. Product team holds final say to avoid design-by-committee.

### Tip 6 — Create a Story with Documentation (p. 14-16)
Personas = cast, use cases = key scenes, wireframes = stage, flows = choreography, UI kit = set design. **"If documentation isn't usable, there's no reason to create it."**

### Tip 7 — Design and Test on Paper (p. 16-18)
Paper prototypes before pixels. Hallway test with 3-5 people. Virtual walkthrough with "human computer" partner.

### Tip 8 — Post Artifacts on a Wall (p. 18-19)
Detective's crime board. One idea per sticky note. Affinity diagrams. Shared physical space infuses UX into team.

### Tip 9 — Build Lo-Fi Prototypes (p. 19-20)
HTML/Keynote/PowerPoint clickable prototypes. Test interaction sequences. "Developers speak the language of interactions."

### Tip 10 — Build Collaboratively (p. 21-22)
Pair design reduces "code blindness." Solo work accumulates blind spots.

## UX Process Map (p. 22)
**Define Problem** → **Resources** → **Collaboration** → **Ideation** → **Creation** → **Test and Refine**

Each phase has probing questions:
- Symptoms? Who's affected? Why solve?
- Who helps? What tools? What time?
- Team alignment, cadence
- All possible solutions; user engagement contexts
- "Design ten ways to solve"
- Easy to use? Solves problem? Users understand? Knowledge gaps?

## Anti-Patterns
- Designing for "everybody" → scope creep
- Whack-a-mole symptom-fixing
- Design-by-committee
- Tunnel vision on perfect doc
- Heavy reports nobody reads
- Premature pixel commitment
- Desk-bound designer-as-island

## Key Quotes

3. "Scope creep is a direct result of not knowing your users well enough." (p. 8)
