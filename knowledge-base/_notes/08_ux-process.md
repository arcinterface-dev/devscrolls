# Getting Started with UX Design Process & Documentation — Extraction Notes

## PDF Metadata
- **Title:** Getting Started With UX Design Process & Documentation
- **Authors:** Guiseppe Getto & Jerry Cao, UXPin Inc., 2015
- **Page count:** 32 pages

## Core Theses
1. UX is recursive, not linear.
2. Theory + Practice + Reflection = the only path to competence.
3. Personal tagged resource library > memorizing terms.
4. **Maintenance comes first, not last.**
5. Prototypes are MVPs for testing, not specs for developers.
6. Personas are the seed of all user-research documents.
7. **Adopt a learner mindset, not a knower mindset.**

## Principles

### 1. Pair Stages with Skill Sets (p. 7-10)
Each design stage paired with skill set produces concrete deliverables.

### 2. Personalized Tagged Library (p. 8-9)
Build searchable collection of resources, organized by skill area.

### 3. Theory → Practice → Reflection Loop (p. 9)
"Knowing isn't enough. You have to practice... think, practice, reflect."

### 4. Preliminary Research Is Most Neglected (p. 10)
"One of the most important" stages. Articulate stakeholders even if just self.

### 5. Contextual Inquiry Over Abstract Assumptions (p. 11)
Interview users in their setting. Ethnography roots.

### 6. Empathy Pipeline (p. 11)
Listen → Simmer → Find Patterns → Walk in Shoes → Support
(Develop empathy → Apply empathy)

### 7. Two Project Types (p. 11-12)
- **Hypothetical**: redesign known products
- **Client-based**: real value to local businesses/nonprofits

### 8. Personas as Foundation (p. 13)
Demographics + Behaviors & beliefs + Characteristics (0-5 scales) + Goals.
**"All user research documents grow out of the persona."**

### 9. User Stories: As a... / I want to... / So that... (p. 13-14)
Each persona gets multiple stories. Collaborative spreadsheet.

### 10. User Scenarios: User + Task + Environment (p. 14)
Adds human/situational details. Builds empathy beyond understanding.

### 11. User Flows + Task Analysis (p. 14-15)
Path mapping reveals friction before code.

### 12. **Maintenance Comes First** (p. 16-17)
Begin IA/content-strategy deliverables BEFORE design. Update them as you go.

### 13. IA vs Content Strategy (p. 16-17)
- **IA** = structure of information and flows
- **Content strategy** = user-facing considerations on top

### 14. Sitemaps (forest) + Wireframes (tree) (p. 18)
Two altitudes of same system. Both needed.

### 15. Taxonomies = Controlled Vocabularies (p. 18)
Not content repositories. Ensure information is usable, valid, controlled.

### 16. Content Governance Plan — 4 Required Elements (p. 19)
a) Clear goals for content development/governance
b) Content calendar
c) List of content repositories
d) Schedule for content audits/inventories

### 17. Prototypes ≠ Final Product (p. 20-21)
Don't constrain developer choices. Don't clutter with UI to be decided later. **MVPs for user testing.**

### 18. Fidelity Ladder (p. 21-23)
Wireframe (static, structure) → Prototype (clickable) → Mockup (visual). Flexible order.

### 19. UI Elements Scale with Fidelity (p. 22)
Atomic components added as prototype matures.

### 20. User Testing Pragmatism (p. 24)
"Where well-laid plans oft go awry." Combine stages under time constraints. Lightweight testing is legitimate.

### 21. One-Page Usability Test Plan (p. 25)
Background, goals, objectives, methodology, sample size. Scannable.

### 22. Testers Match Personas (p. 25)
"Test users should be versions of your personas."

### 23. "Crap Sandwich" Reports (p. 26-27)
What worked → what didn't → next steps. Constructive framing.

### 24. Stakeholders Must Immediately Understand (p. 27)
Why, when, how, key takeaways. Executive-ready summaries.

### 25. Journey Maps Include Pain Points (p. 28)
Goes beyond user flows. Phases, expectations, processes, pain points + mitigations.

### 26. Always Test Each Iteration (p. 29)
"Almost impossible to guess how real users interact." Iteration without testing is theater.

### 27. T-shaped Skills (p. 30-31)
Generalist across all fields, specialist in what interests most.

### 28. Learner Mindset (p. 31)
**"Think of yourself as a learner, not a knower."** Humble, willing to try new things, willing to admit uncertainty.
